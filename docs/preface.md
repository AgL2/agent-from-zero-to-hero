# 前言：为什么写这本书

## 一个真实的困惑

2023 年春天，AutoGPT 在 GitHub 上约两个月冲到十万 star，"Agent"这个词随之从技术术语变成了科技媒体的头条。三年过去，LangChain、Dify、MCP、Claude Skills 轮番登场，每几个月就有一个"革命性"的新框架诞生。

但如果你问一个想入行的人："到底什么是 Agent？"他大概率会先被教程里扑面而来的 LangChain API 吓退，然后陷入一个更深的困惑：**我连 Transformer 都没搞懂，怎么可能搞懂 Agent？**

这不是读者的问题，是学习材料的问题。市面上的内容要么是"三分钟用 xx 框架搭一个 Agent"的快餐教程（你会调用，但不知道为什么），要么是直接从注意力机制讲起的论文解读（你知道原理，但不知道怎么变成产品）。**中间那条从"零"到"专家"的完整路径，一直是断的。**

这本书想做的，就是把这条路修通。

## 这本书的野心：一次讲完一条完整的链路

Agent 不是一个孤立的技术，它是一座塔的塔尖。塔基是神经网络，塔身是大语言模型，塔尖才是自主智能体。所以这本书选择了一条"看似绕远、实则最短"的路线：

```
神经元 → CNN → 反向传播          （模型如何学习）
  → Token → 位置编码 → Transformer （LLM 如何工作）
  → Agent 循环 → 工具调用 → MCP    （Agent 如何行动）
  → RAG → 记忆 → Skill → 多 Agent  （Agent 如何规模化）
  → 三个完整实战项目               （把一切串起来）
```

学完第一部分，你将能手写反向传播；学完第二部分，你将能手写 Transformer；学到第六部分，你将能手写一个 253 行的 Agent 框架，而那时你会清楚地知道，**每一行代码为什么是这样**。

## 本书的三个承诺

**1. 零黑箱。** 书中所有核心概念都配有"手算一遍"或"手写一遍"：手算 3×3 卷积、手推 2-2-1 网络的反向传播、手算三个 token 的注意力、手写 mini-BPE 分词器。看懂一个数字怎么算出来，胜过读十遍概念定义。

**2. 代码真实跑过。** 书中绝大多数代码都在真实机器上运行过，展示的输出也都是程序的真实输出（部分章节甚至保留了"翻车现场"，比如灾难性遗忘实验里那个反直觉的失败结果）。绝大多数代码你照着敲就能复现。

**3. 诚实的工程视角。** 我们不只讲"怎么搭"，更讲"什么时候不该这么搭"：什么任务不该用多 Agent、RAG 和长上下文谁取代谁、为什么你的工具调用总在生产环境翻车。每一章的"常见误区"和"面试高频"栏目，都来自真实的工程和面试现场。

## 这本书适合谁

- **想转行/入行 AI 的工程师**：从第一部分开始，一步不跳
- **懂深度学习、想转 Agent 方向的算法工程师**：可从第三部分切入，需要时回查前两部分
- **想用 Agent 解决实际业务问题的产品/运营/创业者**：重点读第三、四、六部分，理解能力边界比写代码更重要
- **面试准备者**：每章的"🎯 面试高频"就是为你准备的

## 一些阅读建议

1. **不要跳读第一、二部分。** 哪怕你觉得"我只是想做 Agent"，反向传播和注意力机制理解不扎实，后面所有内容都是沙上建塔。
2. **每个实验都要亲手跑。** 这本书的代码不是用来"看懂"的，是用来"跑通—改坏—修好"的。
3. **练习题比正文更重要。** 每章的练习题涵盖手推、编程与思考三类，做不出来的地方就是没真正学会的地方。
